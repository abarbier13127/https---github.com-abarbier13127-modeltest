Chaque objet en référence un autre par une chaîne de caractères. Les pastilles de couleur repèrent ces clés de jointure : deux champs portant la même lettre doivent contenir exactement la même valeur.

Le même schéma, trois fois

Chaque offre GPU a sa propre chaîne profil → LocalQueue → ClusterQueue → ResourceFlavor.

gpu-l4 → lq-l4 → cq-l4 → l4
gpu-h200-full → lq-h200-full → cq-h200-full → h200
gpu-h200-mig-* → lq-h200-mig → cq-h200-mig → h200

Ordre d’application

  1. Opérateurs : cert-manager, Red Hat build of Kueue, NFD, GPU Operator.
  2. MachineSets L4 et H200 avec label de pool et taint.
  3. ClusterPolicy et ConfigMap MIG, puis label mig.config sur chaque nœud H200.
  4. DataScienceCluster (Kueue Unmanaged) et OdhDashboardConfig.
  5. ResourceFlavors, puis ClusterQueues avec les quotas.
  6. Label Kueue et LocalQueues dans chaque projet.
  7. HardwareProfiles de type Queue.

Si je change…

  • le label mig.config d’un nœud : revoir les quotas (Q) et les profils MIG proposés.
  • le label de pool d’un MachineSet : revoir le ResourceFlavor (A).
  • un nouveau projet : créer ses LocalQueues et poser le label Kueue (I).
  • une nouvelle taille MIG : ConfigMap, ClusterQueue (F, Q), puis un nouveau profil.
